NuGet library and documentation site

JWT Validator

Validate a JWT in C# in a few readable lines, without learning Microsoft's IdentityModel types first.

Problem

After an OpenID Connect sign-in, an application must check the ID token before it trusts it. I kept seeing developers struggle with this. Microsoft's own types for it, such as TokenValidationParameters and JwtSecurityTokenHandler, are powerful but hard to use correctly.

What I built

A library with four small parts: an options builder that sets what to check, a validator that says whether the token is valid and returns its claims, an expiry checker, and extension methods for reading the claims. Version 2.0.0 targets .NET 10. A separate site documents it, and every code example on that site is a real program that the pipeline compiles.

Key decisions

How should a new version reach NuGet?

Why: Only one job, which runs only for a tag, can ask for a publish key, and that key lasts one hour. No key is stored anywhere. A version on nuget.org can never be replaced, so the package that is published is the exact package the tests passed on.

How do the documentation examples stay correct?

Why: The site shows each file’s own text. If the library or a page changes and an example breaks, the build fails before the site is published.

How do the tests check the exact moment a token expires?

Why: A test can set the time to the exact second, and the public API does not change for anyone who uses the library.

Draughts Game

Play draughts against another person on the same device, or against the computer at three levels.

Problem

I built this game in memory of my grandad, using the house rules we played together. Read about him on the game's About page.

Those rules are not standard English draughts. Captures are optional, and a man cannot capture a king. So no ready-made engine would play them, and the computer opponent had to be written for these rules.

What I built

A React web app for the board, and an Azure Function that plays as the computer and shows a player the squares they can move to. The function searches ahead for the best move. Easy plays at random, Normal looks up to 6 moves ahead, and Hard searches as deep as it can in one second.

Key decisions

How does the computer stay quick at every level?

Why: Normal stops after half a second and Hard after one second, whatever the position. The search keeps the result of the last depth it finished.

Which rules does the game follow?

Why: They are the rules I played with my grandad, and the reason the game exists. The rules are fixed in both specifications.

How do I know the levels really are different?

Why: The strength targets are numbers, not a feeling: Hard must score at least 80% against Normal, and Normal at least 90% against Easy.

Timer-triggered Azure Function

Picktime Automation

Books my archery club's indoor targets the moment they open, so I never book by hand.

Problem

The club books its indoor targets on Picktime. Each slot opens exactly 7 days ahead, at midnight, and it is first come, first served. Booking by hand meant being awake at midnight three times a week, all winter.

What I built

An Azure Function that runs at 00:05 London time on Tuesday, Thursday and Friday. It books 17:00, 18:00 and 19:00, seven days ahead, on target 2b. Where 2b is taken, it books 3a. It books only in the indoor season, 1 October to 31 March. The days, hours, targets and season are settings, so a change needs no code.

Key decisions

What happens when a booking request times out?

Why: Creating a booking is not safe to repeat. After a timeout, the booking may already exist, and a blind retry could book the same slot twice.

How does it know what "7 days from now" means at midnight?

Why: The server runs in UTC. Just after midnight in British Summer Time, UTC is still the day before, so the wrong date would be booked.

Should the three bookings be sent together to save time?

Why: It takes about 20 seconds, which is still long before anyone else books. If a run fails part of the way through, it is clear which bookings were made.
