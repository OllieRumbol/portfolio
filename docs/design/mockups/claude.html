How I work with Claude

I use Claude Code to build, inside a setup I wrote myself. Every project goes through the same six steps, and nothing starts until the step before it is approved. Independent reviewers check every change. After each project, what went wrong becomes a change to the setup, so the next project starts from a better place.

Planning skills

planning-docs and review-plan

Specification, plan and tasks are written from fixed templates, and approved in that order, before any code.

Agreeing what and how first costs less than rework. A separate review reads all three together, and looks for gaps and contradictions before the first task starts.

spec.md→plan.md→tasks.md→review-plan
“Your job is to find what will go wrong during coding if the documents are approved as they are.”review-plan

Task skill

do-task, added 20 October 2026
From the Picktime retrospective

One task at a time, on its own branch, with its own pull request.

Each change is small enough to review properly, and the pull request records the evidence: tests, reviews and every finding with its outcome.

task/t16-computer-player→Pull request 34→Merged
“Calling this skill is the explicit request to commit and push. Do not merge.”do-task

Reviewers

2 agents and /code-review

Every task is reviewed by reviewers that never see the working conversation.

A reviewer that has followed the reasoning tends to accept it. A fresh one sees only the result, so it judges the work and not the story.

SeesThe diff, the task, the specification and the plan
Never seesThe conversation that wrote the code

Build hook

A Stop hook, 284 lines of Python

Claude cannot finish a turn while C# code it changed does not build.

A broken build is caught in the same turn, not later in CI. It builds only my own repositories, because a build can run commands from the project files.

Example of a blocked turn

> Turn ending. C# files changed.
> dotnet build
  error CS0103: The name 'board' does not exist
> Turn blocked. Errors passed back to Claude.
> Fixed. Build succeeded. Turn ends.
“Stop hook: do not end a turn with C# code that does not build.”dotnet_build_check.py

Retrospectives

retrospective skill

After every project, the setup changes from evidence, not from memory.

A script reads the session history for corrections and interruptions. A change is proposed only for a problem that happened twice, or once at a high cost, and I approve each one.

Everything runs inside free tiers. A cost needs my approval first.
